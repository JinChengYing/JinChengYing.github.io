01 / CONCEPTS

先分清系统、训练与任务边界

Agent 是与外部环境交互的系统或行为范式；Agentic RL 是利用交互反馈更新策略的训练范式。ReAct 式多轮工具调用本身不代表经过 RL 训练。以固定问题的最终答案作为奖励的 RLVR，也未必涉及外部环境状态的改变。

01

能力轴

规划、工具使用、记忆、推理、感知、自我演化和协作。它说明 Agent 在做什么。

02

学习问题轴

策略优化、信用分配、探索、奖励可靠性、信念建模、持续学习与训练效率。它说明行为如何改进。

03

应用与环境轴

代码、搜索、网页、GUI、具身和多智能体任务。它决定可观测性、动作空间、验证方式和成本。

建模边界

在 token 粒度下，普通文本生成也可以是多步 MDP；Agentic RL 的关键在于动作对外部状态和后续观测的影响。工具结果随机不等于环境非平稳；只有转移或奖励规律随时间变化时，才需要非平稳建模。POMDP、可变时长工具动作的 SMDP，以及兼顾任务完成与信息获取的 dual control，是有用的理论视角。

基础索引：Zhang 等，arXiv:2509.02547（2026 年 4 月 v5）↗。该综述采用能力与应用分类；本页增加学习问题轴，属于本站编辑性整理。

值得实验的问题
  • 能否只在关键决策点使用细粒度奖励，把其余轨迹交给较便宜的终局奖励？
  • 工具结果有噪声、信念估计不准时，优势估计应如何表达不确定性？
  • 额外评价预算有限时，优先评估哪些状态？

这些是本站提出的实验设想；反事实贡献需要可重放或可干预环境才能较可靠地估计。

03 / SIGNALS

奖励可靠性与探索应单独研究

结果奖励容易自动化但稀疏；过程和进展奖励更细，却可能引入标注或 verifier 偏差；内在奖励能支持信息收集，也可能偏离最终任务。研究开放式任务时，应同时记录奖励来源、成本、失败类型和可验证范围。

结果任务是否完成易核验，但延迟
过程局部动作是否合理细粒度，成本高
信息是否减少不确定性利于探索，可能偏题
成本token、工具、延迟贴近部署，需明确权衡
安全约束不能只靠加权奖励

成功率、延迟与工具费用可以展示 Pareto 权衡；越权或危险操作应另设硬约束、动作屏蔽与独立验证。Reward Modeling 关注信号是否可信；Credit Assignment 关注怎样把信号分配给动作。

04 / CAPABILITIES

规划、工具、记忆与多轮交互

规划：何时重新规划？

区分推理时搜索、RL 训练的规划策略、分层子目标和基于环境模型的规划。搜索成本与计划失效是现实约束。研究问题是学习何时规划、何时执行，以及能否复用可迁移的子目标。

工具：多步、多轮、多会话

多步指一次任务内多次决策；多轮指 Agent 与环境或用户反复交互；多会话指独立任务间持续积累经验。一个回合可包含零个、一个或多个工具调用，工具组合与回合数是不同维度。

记忆：从存储走向决策

区分上下文、情节、语义、程序性记忆，以及由策略控制的写入、读取、更新和丢弃。关键评价是记忆能否改善后续动作，而不只是回答回忆题。

自我演化与感知

语言自我纠错、外部经验或技能更新、参数级策略改进是不同过程。多模态 Agent 还需学习何时重新观察环境，以及如何避免感知误差向规划传播。

05 / SYSTEMS

环境、Harness 与训练器是三层系统

TRAINER

策略更新

优势估计、梯度计算、数据复用与异步训练。例：verl、SkyRL。

HARNESS

交互控制

上下文压缩、工具编排、错误恢复与子任务执行。

ENVIRONMENT + VERIFIER

状态与反馈

状态转移、观测、工具结果及可验证奖励。例：ALFWorld、τ-bench。

Agent Lightning v1.0（He 等，arXiv:2608.17528）↗ 将部署时的 Harness 纳入 RL 训练：Harness 负责交互循环，训练器观察 LLM 请求与响应。这带来重分词、样本合并、优势计算、损失归一化和后端调度问题。论文报告 Qwen3.5-9B 在其特定 SWE-bench Verified 实验中的 Pass@1 从 41.8% 提升到 56.4%；不能外推为普遍收益。

SINKFLEX-RL（Cheng 等，arXiv:2608.10357）↗ 则将环境接口、训练数据流和注意力内存优化放在一起，展示长程工具任务中系统成本也是研究对象。其结果来自论文所述配置，未在本站验证。

系统研究检查点

记录训练与部署时的工具版本、上下文处理、采样策略、环境失败率及 verifier 成本。比较方法时对齐交互预算，避免把更多环境调用误认为算法改进。

06 / PARTIAL OBSERVABILITY

把 POMDP 与信念状态提升为研究主线

网页、工具和多用户环境中，Agent 往往只能看到局部页面或过期的工具结果。理论上的信念状态是 bₜ(s)=P(sₜ=s|hₜ)；实践中可以用自然语言摘要、结构化状态或潜表示近似。核心问题是这些近似能否被校准，是否真的支持信息获取与后续行动。

P1

表示

自然语言、结构化图、潜状态，哪种表示更能保留可行动信息？

P2

主动获取信息

何时继续执行，何时先搜索、观察或询问以减少不确定性？

P3

校准与变化

如何区分观测噪声与环境规则变化，并检测模型的过度自信？

相关已核对工作：ReBel · arXiv:2605.20061 ↗ 关注信念一致性；ΔBelief-RL · PMLR:auzina26a ↗ 关注信息获取带来的目标概率变化。
